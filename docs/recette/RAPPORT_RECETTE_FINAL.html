2. Ce que le dernier cycle a démontré

Le script deploy/preprod/recette-cycle.mjs a été exécuté sur le serveur par l'exploitant. Cette revue n'a pas relu les jetons ni les mots de passe. Les faits retenus sont ceux du journal et le statut de mission communiqué.

  • Cinq connexions : deux clients, deux transporteurs, un administrateur de recette distinct de l'administrateur déjà en place.
  • L'administration refuse un client, un transporteur et l'absence de jeton (HTTP 401). Le tableau, les utilisateurs, les commandes, les forfaits et les journaux répondent HTTP 200 à l'administrateur de recette.
  • Un client ne peut pas marquer un téléphone comme vérifié. L'administrateur de recette le peut pour un compte fictif, et le second appel reste idempotent.
  • L'achat du second client, encore non vérifié, est refusé.
  • Le premier client crée une commande. Le solde ne change pas. La validation ajoute les crédits du pack une seule fois. La validation répétée répond alreadyProcessed et le solde reste stable. Le refus d'une seconde commande n'ajoute rien.
  • La demande « Sable de recette finale » est publiée. L'autre client ne peut pas la lire. Un devis est refusé tant que le contact n'est pas débloqué (HTTP 402). Le déblocage consomme un crédit une seule fois.
  • L'acceptation crée la mission cmw6ykr8q001plbcf2wt7gjic. Le transporteur avance jusqu'à la confirmation. Le client la passe à COMPLETED. Le transporteur ne peut pas la clôturer.

Le mode de paiement relu sur le site est MANUAL. PayDunya reste désactivé dans ce parcours.

4. Ce qui reste hors du parcours réussi

  • Firefox n'a pas été ouvert. Safari ne peut pas l'être depuis cet agent Linux.
  • Les écrans admin « en cours de construction », les notifications côté client et le rôle opérateur ne font pas partie du produit livré.
  • Un client qui appelle l'API d'administration reçoit encore HTTP 401, pas 403. Aucune donnée n'est renvoyée.
  • Les vidéos d'administration, de validation manuelle et de mission n'ont pas été tournées : elles exigeraient d'afficher une session. La vidéo docs/tutorials/verification-deploiement.mp4 montre seulement les pages publiques du serveur déployé.

5. Décision

La préproduction au commit 627cb4f peut rester le build candidat. Elle ne constitue pas une autorisation de bascule. Les prérequis bloquants et les améliorations reportables sont dans le dossier de mise en production.
