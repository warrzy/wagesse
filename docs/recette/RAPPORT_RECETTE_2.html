5. Risques résiduels

  • Les quatre mots de passe de recette d'origine fonctionnent encore sur la préproduction.
  • L'ancien fichier chiffré reste dans l'historique Git du commit précédent. Il devient inutile seulement après la rotation.
  • Le cycle métier essentiel n'a pas été vu de bout en bout : demande, devis, paiement fictif, crédit unique, contact, mission, clôture.
  • Prisma, sharp, postcss, nanoid, source-map-js et jsonwebtoken 8 restent signalés. Le code n'utilise pas les options qui rendent ces avis exploitables, et la signature est limitée à HS256.
  • Les pages admin « en cours de construction », les notifications utilisateur et le rôle opérateur restent non implémentés.

6. Décision

NO-GO. La plateforme n'est pas encore testée de bout en bout sur la préproduction corrigée. Le déploiement de production n'est pas lancé. Pour lever le blocage, le propriétaire doit autoriser, dans cet ordre, la rotation des comptes, le redémarrage de la seule application WAGESSE, puis la restauration d'essai. Les autres applications du VPS ne sont pas modifiées par les scripts préparés.
