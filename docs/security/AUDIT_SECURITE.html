Vérification téléphonique de production

Le numéro est vérifié par un code à six chiffres, valable dix minutes, envoyé par SMS. Cinq essais faux verrouillent le code. Un renvoi attend soixante secondes, avec au plus cinq envois par heure. La réponse HTTP ne contient le code que si OTP_DEBUG_RETURN vaut true et que NODE_ENV n'est pas production. Sur le VPS, NODE_ENV est déjà production : le code n'est donc pas renvoyé. Le drapeau ne doit malgré tout pas être posé.

En production, le fournisseur est HTTP. SMS_PROVIDER=http, SMS_HTTP_URL et SMS_HTTP_KEY viennent d'un fichier root 600, hors dépôt. SMS_ALLOW_SIMULATE reste absent. Sans URL ni clé, aucun SMS n'est délivré et les opérations payantes restent fermées. Le message envoyé est « WAGESSE : code de vérification … Il expire dans 10 minutes. » L'appel réussit seulement si le prestataire répond correctement. phoneVerified n'est écrit qu'après un code accepté.

Le code est conservé dans la mémoire du processus. Un redémarrage invalide les codes en attente. C'est acceptable pour une seule instance systemd. Le passage à un stockage partagé est reportable si une seconde instance est ajoutée.

Désactivation du mécanisme de recette

La route POST /api/admin/recette/verify-phone répond 404 sauf si les quatre conditions sont réunies :

  1. WAGESSE_DEPLOYMENT vaut exactement preprod.
  2. PREPROD_TEST_PHONE_VERIFY vaut exactement true.
  3. Le nom de base dans DATABASE_URL est exactement wagesse_preprod.
  4. L'en-tête Host est preprod.wagesse.fr, 127.0.0.1 ou localhost.

Le compte doit en plus être fictif : numéro 7800 suivi de quatre chiffres, nom contenant « Recette », rôle ni ADMIN ni SUPER_ADMIN. La réponse ne contient pas de code. NODE_ENV=production ne suffit pas à ouvrir la route, parce que la préproduction tourne déjà dans ce mode.

Les trois premières conditions sont dans le commit déployé. Le contrôle d'hôte est ajouté dans le dépôt après cette recette. Il n'est pas encore redémarré sur le serveur. Un fichier d'environnement copié vers un site wagesse.fr échoue déjà si le nom de déploiement ou la base change. Le script deploy/production/assert-env.mjs refuse, sans imprimer les secrets, un fichier qui contient le déploiement preprod, le drapeau fictif, la base de préproduction, le retour de code, la simulation SMS, ou l'absence d'URL et de clé HTTP.
